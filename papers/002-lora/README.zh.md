# 002 — LoRA：大语言模型的低秩适配

[English](README.md)

**论文：** Hu et al., 2021 | **发表于：** ICLR 2022  
**链接：** https://arxiv.org/abs/2106.09685

---

## 背景

GPT-3 有 1750 亿参数。如果你想对它进行全量微调（fine-tune），你需要：

- 为每个下游任务保存一份完整的模型副本（约 350GB，fp16）
- 反向传播遍历所有 1750 亿参数
- 维护优化器状态（Adam 需要额外 2 倍参数量的显存）

如果有 10 个任务，就得有 10 份这样的副本。这在工程上几乎不可行。

Hu 等人注意到一个关键现象：**微调过程中，权重的变化矩阵 ΔW 具有低秩特性。** 换句话说，ΔW 的大部分信息可以被一个远比它小的矩阵捕获——真正有意义的方向集中在一个低维子空间里。

这个观察催生了 LoRA（Low-Rank Adaptation）：

- **冻结**预训练权重 W（不更新，不存梯度）
- 在旁边插入两个小矩阵 B 和 A，只训练这两个矩阵
- 推理时合并回 W，零额外延迟

效果惊人：在 GPT-3 上，LoRA 只需训练约 470 万参数（占总参数的 0.003%），在 GLUE 等基准上性能与全量微调持平。

LoRA 如今已成为参数高效微调（PEFT）方法中最主流的选择，被广泛用于指令调优 LLM、定制 Stable Diffusion 等场景。它的魅力在于：理论上优雅，工程上简洁，部署无代价。

## 核心思想

### 1. 权重更新的低秩分解

对于预训练权重矩阵 W ∈ ℝ^{d×d}，与其学习完整的 ΔW，不如将其分解为低秩形式：

```
ΔW = BA    其中 B ∈ ℝ^{d×r}，A ∈ ℝ^{r×d}，r << d
```

前向传播变为：

```
h = Wx + BAx × (α/r)
```

数量级对比（以 1024×1024 的权重矩阵为例）：

| 方法 | 参数量 |
|------|--------|
| 全量微调 | 1,048,576 |
| LoRA (r=1) | 2,048（0.20%）|
| LoRA (r=8) | 16,384（1.56%）|
| LoRA (r=64) | 131,072（12.5%）|

r=8 时，仅需原参数量的 1.56%，而效果几乎等同于全量微调。这就是 LoRA 的核心魔法。

### 2. 初始化策略：为什么 B=0 至关重要？

LoRA 的初始化方案：

- **B 初始化为全零矩阵**：确保训练开始时 ΔW = BA = 0，模型行为与预训练模型完全相同。
- **A 使用 Kaiming 均匀初始化**：提供 A 矩阵中方向的多样性。

为什么不能随机初始化 B？如果 B 也随机初始化，那么训练一开始 ΔW = BA 就是一个随机矩阵，会立刻"污染"精心训练好的预训练表示，导致训练不稳定。B=0 保证了一个优雅的起点：从原始预训练模型出发，逐渐学习任务特定的"偏差"。

### 3. 缩放因子 α/r

LoRA 的输出乘以 α/r，其中 α 是超参数。

这个设计的好处是：当你改变 rank r 时，不需要重新调整学习率。论文通常设定 α = 2r（等效于缩放因子为 2）。

直觉上，α/r 控制了 LoRA 分支对原始权重的影响力度——α 越大，LoRA 的贡献越显著。

### 4. 权重合并：推理零代价

训练结束后，可以将 LoRA 矩阵合并回基础权重：

```
W_merged = W + BA × (α/r)
```

合并后，模型与原始模型的结构完全相同——没有额外的矩阵，没有额外的计算，没有额外的延迟。

这意味着你可以：
- **热插拔**：将不同任务的 LoRA 适配器随时换入换出
- **无缝部署**：生产环境只需一份基础模型 + 少量 LoRA 文件（几 MB）
- **叠加效果**：理论上可以加权叠加多个 LoRA（如 style LoRA + content LoRA）

### 5. 应该对哪些层加 LoRA？

论文的结论：对注意力层中的查询矩阵（Q）和值矩阵（V）加 LoRA，效果最好。键矩阵（K）和 FFN 层的收益边际递减。这也符合直觉——注意力机制中 Q 和 V 的投影决定了"关注什么"和"提取什么"，是任务适配的关键。

## 实现解析

### 保留了什么

- 精确的 LoRA 公式：ΔW = BA，B=0 初始化，A Kaiming 初始化
- α/r 缩放
- 冻结基础权重，只训练 A 和 B
- 推理时的权重合并
- `apply_lora` 工具函数，可以对任意模型的指定层注入 LoRA

### 简化了什么

- **省略了 LoRA dropout**：论文在 LoRA 分支上加了 dropout 防止过拟合，这里为了清晰略去
- **所有层使用相同的 rank**：论文建议可以对不同层用不同 rank，这里统一处理
- **使用小型演示模型**：没有真实预训练权重，仅展示 LoRA 机制

### 核心代码解读

**LoRALinear 前向传播**（lora.py，约第 60–65 行）：

```python
base = self.linear(x)                                      # 冻结的 W，不产生梯度
lora = (x @ self.lora_A.T @ self.lora_B.T) * (alpha / r)  # 低秩路径，产生梯度
return base + lora
```

注意：`self.linear.weight.requires_grad = False`，所以 `base` 的计算不参与反向传播。梯度只流经 A 和 B。

**权重合并**（lora.py，约第 68–75 行）：

```python
delta = (self.lora_B @ self.lora_A) * (self.alpha / self.rank)
self.linear.weight.add_(delta)  # 就地加到 W 上，之后可以删掉 A 和 B
```

**apply_lora**（lora.py，约第 85–100 行）：遍历模型的模块树，将目标 `nn.Linear` 层替换为 `LoRALinear` 包装器。这种非侵入式的设计使 LoRA 可以应用于任何基于线性层的模型。

## 关键收获

### 1. 低秩假设究竟有多强？

论文通过实验验证了这个假设的合理性：他们分析了全量微调时不同层的 ΔW 矩阵的奇异值谱，发现绝大多数奇异值非常小——即 ΔW 确实"接近低秩"。这不是一个启发式的工程技巧，而是有实验支撑的观察。

### 2. rank 该怎么选？

论文的经验结论：

- r=4 到 r=8 对大多数任务已经足够
- 对非常专业化的任务（如代码生成），适当增加 r 到 16 或 32 有帮助
- r 再大收益递减明显，且参数量快速增加

实践中，r=8 是最常见的默认值。

### 3. LoRA vs 其他 PEFT 方法

| 方法 | 核心思想 | 推理延迟 |
|------|----------|----------|
| LoRA | 低秩权重更新 | 无（可合并） |
| Prefix Tuning | 在 KV 前加可训练前缀 | 有（输入变长） |
| Adapter | 在层间插入小模块 | 有（额外前向计算） |
| Prompt Tuning | 只训练软提示嵌入 | 无（但效果较弱） |

LoRA 的"可合并"特性使其在部署上具有独特优势。

### 4. LoRA 在实际应用中的生态

LoRA 已经成为微调 LLM 的事实标准：

- **Hugging Face PEFT 库**：原生支持 LoRA，一行代码即可注入
- **QLoRA**（2023）：将 LoRA 与 4-bit 量化结合，65B 模型可在单张消费级 GPU 上微调
- **Stable Diffusion DreamBooth**：用 LoRA 定制特定风格/人物，文件只有几 MB
- **LLaMA-Factory、Axolotl 等微调框架**：内置 LoRA 支持

理解 LoRA 是理解现代 LLM 微调生态的基础。

### 5. 一个值得思考的问题

为什么大模型的微调本质上是低秩的？一个合理的解释是：预训练已经学到了几乎所有的通用知识，微调只需要"选择激活哪些已有知识"，这个选择操作本身是低维的。换句话说，**微调不是在学新知识，而是在给已有知识重新排列优先级。**
